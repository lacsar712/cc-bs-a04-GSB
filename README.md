# 桥梁应变班交台

同一跨段必须**成对双测**才许入队。测量员先在 **双测配对专页** 登记主测点与副测点编号，再在首页**同一次提交**两个微应变读数：

- `|主读数 − 副读数|` 超过**差值门槛**（默认 20 με，可在专页调整）→ **整笔退回**，批次记为退回并写明「双测超差」，出现在专页「退回样例」。
- 差值合格 → 两条读数入候审队列，后台工人用 `FOR UPDATE SKIP LOCKED` 按批次认领，按 **80～220 με** 判定 **合格 / 越界**。
- **配对随单冻结**：入队即在同一事务把配对置 `frozen`，主副点号与当前门槛随批次快照；事后改配对表不影响旧单点号。
- **并发互斥**：入队与配对冻结一次写完，两人同时提交同一对时至多一笔成功（另一笔 409）。
- 权限：测量员可维护配对/门槛并报送；复核员可查看配对表、批次与双测差值，但不能改配对、不能报送。

## 页面

| 顶栏入口 | 内容 |
|----------|------|
| 首页 · 双测报送 | 跨段 + 主读数 + 副读数三个框一次提交；双测批次表；读数明细 |
| 双测配对专页 | 配对维护、差值门槛设置、退回样例（首页的两个读数框不算专页） |

## 技术栈

| 层 | 选型 |
|----|------|
| 接口 | Python Sanic + psycopg（异步连接池） |
| 工人 | `worker.py`（psycopg 同步，按批次 `FOR UPDATE SKIP LOCKED`） |
| 页面 | Mithril.js + Vite，nginx 反代 `/api` |
| 数据库 | PostgreSQL 16 |

## 主要接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/pairings` | 配对表（全员可看） |
| POST | `/api/pairings` | 登记跨段主副测点（仅测量员） |
| PUT | `/api/pairings/<id>` | 修改未冻结配对（冻结后 409） |
| GET/PUT | `/api/config` · `/api/config/threshold` | 读取/设置差值门槛（写仅测量员） |
| POST | `/api/batches` | 同单双测提交；超差 422 退回，重复同对 409 |
| GET | `/api/batches` | 双测批次（含候审、已判定、退回样例） |
| GET | `/api/readings` | 成对读数明细（含主副角色、双测差值、门槛快照） |

## 验收走查

1. 在专页为「跨中甲」登记主、副测点。
2. 首页选「跨中甲」，主读数 **150**、副读数 **155** → 差值 5 ≤ 门槛，批次与两条读数**进候审**，配对变「已随单冻结」。
3. 再次报送同对 → 409（同对至多一笔）。
4. （另一跨段或门槛允许时）主 **150**、副 **190** → 差值 40 > 门槛，**整笔退回**，专页退回样例写明「双测超差」。
5. 用 reviewer 登录：配对表/批次/差值可见，但无配对维护、门槛保存与报送入口。

## 启动

```bash
cd projects/19-bridge-strain-shift
docker compose up --build
```

健康检查：`GET http://localhost:8198/api/health` → `{"status":"ok","service":"bridge-strain-shift"}`

## 本地开发（可选）

```bash
cd backend && pip install -r requirements.txt
python -m sanic api.app --host=0.0.0.0 --port=8000 --single-process
python worker.py
cd frontend && npm install && npm run dev
```

接口进程默认监听容器内 **8000**，对外映射 **8198**。
